HARD RULES
1. Output ONE JSON object only (no prose, no code fences).
2. The week is DATA, never code. No HTML, CSS, SVG, JavaScript, URLs, file paths, image paths or data: URIs anywhere. Colours are '#rrggbb' only. Emoji characters are fine. Use only the hosted kinds provided, with exactly their fields (extra fields are rejected).
3. Answer keys. Every worksheet that has gradable items carries `answers`: a list of {"item_ref", "answer"} using only the item_ref shapes given for that kind, one entry for EVERY item_ref of the page. The answer must be correct and match the worksheet content exactly. Arithmetic answers are checked by machine: write the bare number ("7"). An item_ref addresses a slot the child fills in; content already printed on the page (a pre-filled cause, a given example) has no item_ref and must not be answered. Open-response pages (writing frames, letters, story maps, task lists) may omit answers; the teacher guide then says what a good response contains.
4. Matching pages print left_items[i] on the same row as right_items[i]. Put right_items in a DIFFERENT order from the left items so no row shows its own answer; the answers then name the right item each left item belongs with, and every right item is used exactly once. Shuffle word banks, sort tiles and fill-in lists so the displayed order never matches the answer-key order or the passage order.
5. Every readingWorksheet: `instructions` frames a brief hands-on or active warm-up (indoors or outdoors) before/during/after reading, tied to that day's idea; vocabulary of 3-4 terms; three or four questions; the LAST question is an oral "LET'S DISCUSS: ..." prompt with response_lines 0 (a tricky real-world case that applies the day's idea).
6. A recurring narrator character (the PLAN names them): introduce them on Monday with a "meet <character>" sentence before the lesson content; keep the hook alive on later days. Connect the child's interests to the content naturally; do not force every page.
7. The child's first name may appear only as the literal token {{student_name}}; never write the actual name anywhere (not in titles, passages, the teacher guide or prep checks), and no other {{...}} placeholder exists.
8. Student-facing text must be readable at the child's reading level (see STUDENT): short sentences, common words, one idea per sentence; define new words in context. Follow the parent's notes about the child's temperament and writing load. Favour hands-on, drawing, circling, matching, sorting and short oral answers over long writing. Each worksheet must fit on ONE letter page. Facts must be true and standard for the grade; never invent statistics, quotes or events.
9. Prep checks: about 10 total (two per day, never fewer than 8), each with a standard_id taken from the STANDARDS list, a kind in quiz|oral|review|activity|observation, a prompt the parent can say aloud or do in two minutes, and a plain-words pass_criteria. Ids chk-1, chk-2, ...
10. Every Day.standards entry and every prep check standard_id must come from the STANDARDS list, character for character. Cover every listed standard at least once across the week.
11. Worksheet ids are unique lowercase slugs such as mon-1, tue-2. Days are Monday, Tuesday, Wednesday, Thursday, Friday, in that order, at least 2 worksheets each (a reading page plus one or more application pages; Friday is a capstone).
12. No empty strings in text fields, no placeholder text (no "TBD", "lorem", "...", "[insert").
13. Shape reminders. The top level has "schema_version": 1. A teacher_guide block is EITHER a heading block {"heading": "..."} with nothing else, OR a callout block {"style": "answer|misconception|extension|discuss", "paragraphs": ["..."]} with no heading; to title a callout, put a separate heading block before it. teacher_guide.meta is a list of ["Label", "Value"] pairs. Every teacher_guide day (all five) holds an `answer` callout (the day's answers with a short explanation), a `misconception` callout, an `extension` callout and a `discuss` callout.
